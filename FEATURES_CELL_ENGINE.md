# Фичи второй (сложной) таблицы: домен `cells` и CellEngine

Этот документ описывает функциональность, которая была добавлена для работы со
**сложными шихтовочными листами** — второй таблицей проекта: **«2 блок»**,
**«3 блок»**, **«Отклонения от БЮДЖЕТА и ПЛАНА»** (файл
`data/Faked_List_proportional (2).xlsx`). В отличие от лёгкой витрины
`mart.price_facts` / `mart.metrics`, здесь данные не нормализуются в
«цена/поставщик/период», поэтому обработка вынесена в отдельный домен **`cells`**
и отдельный вычислитель **CellEngine**.

## 1. Чем сложные листы отличаются от лёгкой таблицы

| | Лёгкая таблица | Сложная таблица |
|---|---|---|
| Данные | `mart.price_facts` (цены), `mart.metrics` (план/факт) — нормализованная long-форма | Нерегулярная сетка ячеек: подписи поставщиков, проценты, стоимости, итоги вперемешку |
| Шапки | Осмысленные (наименование / цена / период) | «Пустые»/служебные, реальные данные разбросаны по сетке |
| Тип вопросов | «цена/поставщик/период», агрегации AVG/MIN/MAX | Явные A1-координаты (`C20`, `D20`, `M61`, `F57`), семантические метки («фактическая доля», «утверждённый план»), вычисления между ячейками |
| Обработчик | SQL-пайплайн (`planner → codegen → executor → verifier`) | CellEngine (LLM по «сетке ячеек», без генерации SQL) |

## 2. Детекция cell-запроса

Функция [`looks_like_cell_query`](../src/services/agent/cell_detect.py:49)
детерминированно решает, что вопрос относится к сложной таблице, если:

- есть **явная координата ячейки** Excel — regex `_CELL_REF_RE`, например `C20`,
  `M61`, `E84`;
- есть **упоминание столбца/колонки/ячейки + буква** — `_COLUMN_REF_RE`
  («столбец G», «колонка M»);
- есть **подсказка сложного листа + ключевое слово** — `_looks_like_complex_table_query`:
  лист из `_COMPLEX_SHEET_HINTS` («2 блок», «3 блок», «отклонени», «бюджет»)
  И ключевое слово из `_COMPLEX_KEYWORDS` («расход», «силос», «доля»,
  «стоимост», «шихт», «фактическ», «утвержден», «план», «факт», …).

Помощник [`infer_cell_query_type`](../src/services/agent/cell_detect.py:62)
подбирает `query_type` по словам вопроса (сумм → `sum_by_supplier`, разниц →
`delta`, сравн/выше/ниже → `cross_sheet`, максим/средн → `aggregate`, иначе →
`lookup`).

## 3. Домен `cells` и маршрутизация в CellEngine

1. В [`graph_state.py`](../src/services/agent/graph_state.py) определён
   `Domain.CELLS = "cells"` и константа узла `NODE_CELL_ENGINE`.
2. В [`classifier_node.py`](../src/services/agent/nodes/classifier_node.py:165)
   детектор `looks_like_cell_query` имеет **приоритет над LLM-доменом**: если он
   сработал, домену присваивается `Domain.CELLS` вне зависимости от ответа LLM.
3. В [`routing.py`](../src/services/agent/nodes/routing.py:26)
   `route_after_classifier` направляет запросы с `Domain.CELLS` сразу в
   **CellEngine**, минуя disambiguation → planner → codegen → executor → verifier.
4. В [`graph.py`](../src/services/agent/graph.py:67) узел `cell_engine`
   подключён к графу; после него маршрут идёт напрямую в `answer`.

Правило `route_after_cell_engine` всегда завершает граф через `answer` —
CellEngine заполняет ответ даже при ошибке (fallback-сообщение).

## 4. Представление `mart.cells` и доступ к сетке через SQL

Для адресации по настоящим координатам создано read-only представление
[`mart.cells`](../src/core/db/cells_view.py) поверх `public.cells + public.sheets`:

- колонки: `sheet_id`, `file_id`, `sheet_name`, `sheet_norm_name`, `row_num`,
  `col_index`, `cell_ref` (вида `C20`), `value_number`, `value_text`,
  `value_numeric`;
- функция [`a1_ref(col_index, row_num)`](../src/core/db/cells_view.py:20)
  превращает числовые индексы в буквенно-цифровую ссылку;
- `value_numeric` приводит текстовое число к `double precision` (в т.ч. с запятой).

Представление и функция создаются **идемпотентно** (`CREATE OR REPLACE` /
`DROP IF EXISTS`) при каждой загрузке файла в
[`ingestion_service.py`](../src/services/excel/ingestion_service.py:31)
через `ensure_cells_view`. Ошибка здесь некритична для обычного пайплайна цен/метрик.

В компиляторе SQL `mart.cells` добавлена в белый список
[`ALLOWED_TABLES`](../src/services/agent/sql_compiler.py:33) с ограниченным
набором колонок (`_CELLS_COLUMNS`), остаётся read-only.

## 5. Хранение истинных координат

В [`repository.py`](../src/services/excel/repository.py:169) ячейки сохраняются с
**настоящими** A1-координатами из исходного Excel (номер строки/колонки без
смещения на размер шапки). Это критично: иначе `C20`, `M61` указывали бы на чужие
ячейки. Сохранение координат не влияет на агрегацию цен/метрик, т.к. она
группирует по номеру строки, а не по абсолютной координате.

## 6. Вычислитель CellEngine

Узел [`cell_engine_node`](../src/services/agent/nodes/cell_engine_node.py:130):

1. Определяет релевантные листы `_resolve_sheet_ids`: из `relevant_sheets`
   классификатора, иначе — поиск по именам-подсказкам из вопроса («2 блок»,
   «3 блок», «отклонени», «бюджет»).
2. Загружает компактную «сетку ячеек» `_load_grid` вида `ЛИСТ|A1: значение`
   (непустые ячейки, до `MAX_CELLS_PER_SHEET = 700` на лист, итого
   `MAX_DUMP_LINES = 900` строк в промпте).
3. Добавляет подсказку по сущностям `_summarize_relevant` (сущности + кандидаты
   из классификатора).
4. Отдаёт сетку структурированной LLM (схема
   [`CellEngineResult`](../src/services/agent/structured_schemas.py:38):
   `answer`, `value`, `cells_used`, `reasoning`). В режиме `concise` используется
   сокращённый промпт `CONCISE_ENGINE_PROMPT`.
5. Заполняет `state["answer"]`, `state["sql_query"] = "// cell-engine (сложная таблица)"`,
   `sql_result` с использованными ячейками и пояснением, а также `trace`.

Инструкции в системном промпте `CELL_ENGINE_SYSTEM_PROMPT`:

- находить значения по текстовым подписям строк (обычно колонка B) и смыслу колонок;
- учитывать все строки поставщика при одинаковой подписи;
- сумма по столбцу = сумма ненулевых значений нужных строк;
- для «плана» и «факта» брать соответствующие ячейки (план обычно левее факта);
- доли в % уже проценты — не переводить повторно;
- округлять разумно (обычно 2 знака) и указывать единицы из вопроса;
- возвращать естественный ответ на русском + `value` + `cells_used` + `reasoning`.

## 7. Ответ для CellEngine не перегенерируется

В [`answer_node.py`](../src/services/agent/nodes/answer_node.py:83) для домена
`cells` (`is_cell_domain`) повторная генерация ответа через SQL-пайплайн
**отключается** — готовый вычисленный по A1-координатам ответ CellEngine
сохраняется как есть, чтобы не исказить точные числовые результаты.

## 8. Схема работы на примерах

| Вопрос | Путь обработки |
|---|---|
| «Какое значение в ячейке C20 листа „2 блок“?» | Classifier → `Domain.CELLS` → CellEngine → читает `mart.cells` по `cell_ref=C20` → ответ |
| «Суммарный расход из силосов по Краснокаменской КЖ …» | Классификатор находит лист «2 блок», CellEngine суммирует по строкам поставщика |
| «На сколько п.п. факт отличается от плана …?» | CellEngine берёт ячейки факта и плана, считает разность |
| «Сравните стоимость шихты 2 и 3 блоков» | CellEngine загружает оба листа и сравнивает ячейки `F57`/`M57` |

## 9. Что НЕ менялось (защита лёгкой таблицы)

- Пайплайн `mart.price_facts` и `mart.metrics` работает как раньше.
- Классификатор направляет в CellEngine только запросы домена `cells`; остальные
  идут прежним путём (disambiguation → planner → codegen → …).
- SQL-компилятор по-прежнему read-only; `mart.cells` добавлена в белый список с
  ограниченными колонками.

## 11. Эксплуатация

- Файл Faked_List должен быть загружен через API (upload) — при этом
  автоматически создадутся ячейки `cells` и представление `mart.cells`.
- Для вопросов со сложными вычислениями (взвешенные средние по долям блоков)
  точность зависит от полноты сетки ячеек, переданной в LLM; узел ограничивает
  размер промпта (`MAX_CELLS_PER_SHEET`, `MAX_DUMP_LINES`).
